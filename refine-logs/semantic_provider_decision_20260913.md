# Semantic provider decision review — 2026-09-13

Scope: bounded `research-refine` method decision review after surface-owner v1 and v3-style anchor failures. This is not a code review, not a GPU launch recommendation, and not an experiment-integrity verdict. I read the current fact-scope revision/review, CSP implementation/tests, native method model, surface reader failure review, surface v1 witness, structured-alignment notes, and the 9273/14637 concrete artifact. I did not read gold labels, start GPU, or modify implementation.

## Decision

Choose **B: Data2txt typed source-schema relation/unit/quantifier algebra as the next default route**. Keep **A: Qwen3-8B reasoning + full relation questions + pointer citations + CSP joint binding** only as a secondary semantic-provider diagnostic and as a possible natural-text provider after it passes pre-registered canaries. Do not make A the default hard gate for another full run.

This is a narrower claim, but it is the first route that can plausibly break zero contrast without changing the problem into supervised hallucination detection. B uses deterministic source-side semantics where the source format actually provides them: Data2txt Python-literal field paths, scalar values, lists, booleans, nulls, weekly hours, units and record identity. It still needs response-side span/fact matching and relation applicability, but it no longer asks Qwen to discover the source answer or decide absence from open free text before any B/A contrast can exist.

## Facts from the current evidence

- `surface_owner_v1_20260913` completed B36/C36 with `native_forward_calls=0`. It assessed 1619 target slots, opened strict checks for 145 candidates, and produced no usable contrast handoff.
- The independent reader-cache review found no implementation bug in request identity, label tokenization, cache reuse, or label mapping. The finite one-token reader interface itself is semantically unreliable.
- A direct example: in response 15324, the source text contains wintergreen oil used as a flavoring agent in candies, yet the target `candies` was scored `N≈0.904`.
- Another example: in response 6300, replacing `bagels` with `2021-10-27 01:50:28` received `selected_occurrence S≈0.999`, while other gates correctly rejected the edited sentence.
- Case 9273/14637 is decisive for Data2txt: source 14637 has seven days of `hours: 8:0-16:0`, while response 9273 says business hours are `8 AM to 6 PM every day` and also says `free WiFi`. The frozen reader scored the target `8 AM to 6 PM` as `S≈0.962`; `free WiFi` was also `S≈0.962`. The source supports WiFi but contradicts the closing time. This is a typed interval/every-day problem that Qwen's current finite target judgment missed.
- The CSP implementation correctly separates graph solving from semantic truth. It can combine supplied allowed/forbidden/unknown relation tables, but it does not certify those tables.
- Llama3.1 is the observer/replay model. For rows generated by Llama2-7b or other generators, native measurements can only support observer-mechanism claims, not original-generator causal claims.

## Why A should not be the default next route

A fixes the format of the old interface but not its identifiable target. Turning on Qwen reasoning, asking full relation questions, requiring source citations, and letting the model propose overlapping facts may improve some cases, but every decisive semantic object still comes from the same provider: the fact factor, source answer, relation status, condition coverage, owner binding, and often the candidate source span. If A fails, the system returns to zero contrast; if A succeeds on a few cases, it remains hard to tell whether CSP helped or the reader simply guessed the right relation.

The current evidence is not “Qwen needs a better output format.” The 10/10 specified-letter diagnostic and mass near .999 only show transport correctness. The reader saw correctly rendered requests, valid labels and complete source text, then still gave wrong semantic labels. Reasoning mode may change behavior, but it has no independent target unless we test it against source-derived canaries. A should therefore be a **provider candidate**, not the next method backbone.

If A is retained, use it only under this contract:

1. It receives frozen pointer IDs and exact source/response spans, not permission to invent new source answers that enter the same run.
2. It must pass a small source-derived canary suite before driving native: hours interval/every-day, WiFi string, boolean reservation/outdoor seating polarity, category list membership, null field unknown. The 9273 hours case is a required canary.
3. Passing canaries permits `semantic_provider_candidate`, not ground truth. It still needs relation/CSP/contrast artifacts and independent evaluation after prediction freeze.
4. Failure sends natural-text/QA/Summary cases to `semantic_provider_unvalidated`, not to another prompt-only full run.

## Why B is the better next step

B removes the largest unverified burden: open source answer discovery. In Data2txt, the source already has a typed provenance graph. The method can programmatically parse the source literal, normalize fields and values, generate typed source facts, and construct source-supported alternatives for a subset of response facts. Qwen, if used at all, is narrowed to relation applicability over fixed field IDs and fixed response spans.

This directly serves the full method because the later native layer needs actual B/A contrasts. A perfect generic semantic provider is unnecessary to test whether the observer graph can localize source/history dependence, source-vs-history competition, and MLP modulation once a reliable contrast exists. The typed branch is not the whole paper, but it is the cleanest way to produce real natural contrasts without hallucination-label training or a new detector.

B also gives a clear negative boundary. If deterministic typed source algebra plus conservative response matching still cannot produce contrasts on Data2txt, the bottleneck is no longer Qwen formatting; it is response fact identification/semantic applicability. That is useful and finite. If it does produce contrasts, native can finally test the graph mechanism on real natural examples.

## Minimal B specification

### Source side

Parse Data2txt source with a whitelist literal parser, never `eval`. Build a sealed typed source graph:

```text
record_id / field_path / scalar_or_list_value / value_type / parent record / raw span / canonical rendering / unknown status
```

Required typed families for the first pass:

- `hours`: day -> interval, with canonical time rendering and all-days equality/weekday subset tests;
- `attributes.WiFi`: string enum such as `free`, `paid`, `no`, `unknown`;
- booleans such as `RestaurantsReservations`, `OutdoorSeating`, `RestaurantsTakeOut`, parking subfields: polarity only, no free naturalization without a predicate map;
- numeric ratings/stars with units kept separate;
- categories/list membership;
- name/address/city/state as entity/location fields;
- `None` as unknown/null-literal, never as global absence or explicit negative.

### Response side

Use the current fact-scope/surface graph only to provide exact original spans and sentence envelopes. Do not rely on free SRL as a hard precondition. For Data2txt, the first response candidates should be typed surface spans plus local predicate context:

```text
time range / number / string entity / category item / boolean-polarity phrase / list item / null-unsupported commitment
```

The response candidate is not a role truth. It becomes native-eligible only after a typed field relation applies.

### Relation applicability

Use a finite dataset-schema relation map before Qwen reasoning. Examples:

- phrases about opening/business hours -> `hours`;
- WiFi/free wireless -> `attributes.WiFi`;
- reservations/booking accepted -> `RestaurantsReservations` with polarity;
- outdoor seating/patio -> `OutdoorSeating`;
- category/service list claims -> `categories` or review-text family, depending on predicate;
- rating/star claims -> `business_stars` or `review_stars`, with record identity explicit.

This map is a Data2txt schema assumption, not a universal natural-language fact verifier. Ambiguous predicates, review-derived summaries, sentiment claims, and predicates outside the map return `relation_unmapped` and may only receive soft/dependence outputs.

Qwen may be used after this as a fixed finite verifier over field IDs:

```text
applicable_same_relation | different_relation | condition_conflict | ambiguous
```

It cannot introduce a new field, source span, value, or source answer in the same run.

### Typed conflict/support algebra

For each mapped relation, compute source-vs-response status programmatically when possible:

- Interval equality/conflict for hours. In 9273, `8 AM to 6 PM every day` vs seven `8:0-16:0` intervals is `closing_time_conflict`, with `every day` supported and start time supported.
- String enum equality for WiFi. `free WiFi` vs `WiFi='free'` is supported.
- Boolean polarity consistency only when the response has a clear polarity span. `does not accept reservations` vs `RestaurantsReservations=False` is supported; missing polarity span is unresolved.
- List/category membership can support listed categories, but absence from a non-exhaustive review text is not N.
- `None` yields unknown unless the dataset schema explicitly defines it as a negative value for that field, which should be rare and predeclared.
- Numeric/rating fields require exact field path and unit; review stars and business stars are different fields.

### B/A compiler

Construct exact native contrasts only for typed statuses with a complete edit:

```text
B = original response sentence/event up to the same endpoint
A = replace only the typed target span with the canonical source-supported value, preserving all non-target characters
```

For 9273, the hours candidate should compile as:

```text
B: The business hours are from 8 AM to 6 PM every day, and they offer free WiFi.
A: The business hours are from 8 AM to 4 PM every day, and they offer free WiFi.
```

This is valid only because all seven source days share `8:0-16:0`, the response says every day, and the WiFi clause is separately supported. If days differ, response says weekdays/weekends imprecisely, or editing one span leaves a false condition, the compiler must output `contrast_unavailable_condition_mismatch` rather than free rewrite.

For N/missing claims, do not invent a source value. Use a separately named withholding contrast only if a fixed non-commitment phrase can replace the target without changing non-target meaning. Do not mix this with conflict-repair certificates.

### Native handoff

Once B/A exists, reuse the existing CausalOracle/validate path:

- shared-prefix complete-event `F = logP(B) - logP(A)`;
- source/history candidate groups from the observer graph;
- matched controls from the same typed source family when possible;
- raw input -> selected V -> recipient F origin tests only as path mediation, not abstract pointer identity;
- pairedR/MLP interactions only after relation and contrast validity.

Report every native result as an observer Llama3.1 measurement. For Llama2-7b-generated rows, do not claim original-generator cause.

## What this route can claim

If implemented and evaluated cleanly, B can support:

- a no-hallucination-label training method for **typed Data2txt factual mismatch detection and localization**;
- automatic construction of real B/A contrasts for a predeclared subset of structured-source facts;
- observer-model source/history route, origin-path and aggregation witnesses for those contrasts;
- a controlled demonstration that graph/native information improves over schema-only or Qwen-only baselines, if the metrics show it.

It cannot claim yet:

- general QA/Summary hallucination detection;
- pure internal fact attribution without source text or a semantic provider;
- original-generator causal mechanism for non-Llama3.1 generators;
- that Qwen reasoning solves semantic ownership;
- that typed schema rules transfer beyond Data2txt.

## Implementation order

1. Freeze a Data2txt typed source graph and canonical value renderer. Include source spans, field paths, value types, record IDs, normalized intervals, enums, booleans, lists and nulls.
2. Implement deterministic relation/status algebra for a small predeclared field family: hours, WiFi, reservations, outdoor seating, categories, ratings, address/name/city/state. Keep review-text sentiment and open predicates unresolved in the first version.
3. Connect response typed spans to relation context using exact sentence/fact envelopes and conservative lexical/schema triggers. This is candidate generation, not semantic truth.
4. Run a CPU-only canary compile on the 36 development responses before GPU. Required canaries include 9273 hours conflict and 9273 free WiFi support. The artifact must show which fields mapped, which remained unresolved, and which B/A edits are exact.
5. Only after nonzero exact typed contrasts exist, run native observer measurements on those contrasts. Do not run another full expensive native stage if the typed compiler produces zero valid contrasts.
6. Add A/Qwen reasoning as an ablation provider after B is frozen: compare `typed-schema`, `Qwen-reasoning-provider`, and `typed+Qwen applicability`. If Qwen overturns deterministic typed algebra on canaries such as 9273 hours, it is marked provider failure rather than promoted.
7. Evaluate frozen predictions with labels only after artifacts are complete. Report Data2txt typed branch separately from QA/Summary/general branch.

## Required reporting denominators

For the next report, separate these counts:

- Data2txt responses/claims/typed spans total;
- source fields parsed, fields skipped, null/unknown fields;
- response typed candidates by family;
- relation mapped, relation ambiguous, relation unmapped;
- typed support, typed conflict, typed unknown;
- exact B/A repair compiled, withholding compiled, contrast unavailable;
- native observer executed, controls available, origin tested, certificate attached;
- QA/Summary natural cases left under unvalidated semantic provider.

Do not report typed-branch coverage as full RAGTruth coverage. Do not hide unresolved natural cases by moving them out of the denominator.

## Stop conditions

- If B cannot compile at least the obvious 9273 hours conflict into an exact B/A while keeping WiFi supported and non-target text unchanged, stop and debug typed algebra/response span mapping before any GPU native run.
- If B compiles contrasts but native finds only uncontrolled dependence with no matched controls/origin tests, report observer target-dependence only; do not call it route-derived hallucination.
- If A/Qwen reasoning still marks 9273 hours as supported after seeing fixed spans and source field IDs, reject A as a default semantic provider for typed facts.
- If Data2txt typed branch works but QA/Summary remain unresolved, state that the method currently solves the structured-source subproblem and that the generic semantic provider remains open.

## Final recommendation

Adopt B now. It is the smallest route that changes the failed dependency: source-answer semantics move from an unreliable open reader to deterministic typed source algebra where the dataset actually permits it. It gives the native graph a real chance to operate on natural, exact B/A contrasts and provides clear observer-only claims. A remains useful, but only after it is demoted from backbone to measurable provider candidate.
