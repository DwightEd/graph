# Cloze-anchor v3 integration review — 2026-09-13

Reviewed the active v3 integration only: `cloze_anchor.py`,
`cloze_prompts.py`, `evidence_anchor.py`, `atomic_anchor.py`,
`frozen_reader.py`, `json_framing.py`, `audit_prepare.py`,
`audit_protocol.py`, `audit_runner.py`, and the specified cloze tests. This is
an engineering review of the A-stage semantic interface. It does not assess
the preserved v1/v2 snapshots or make a result claim about native auditing.

## Result

**Critical 1, Required 3.**

### Critical

1. **The independent VERIFY call cannot cross the ClozeReader boundary.**
   `_source_anchor()` deliberately builds its blind VERIFY request with
   `source_answer: None` at `evidence_anchor.py:136-140`. `ClozeReader.ask()`
   rejects every SOURCE/VERIFY request whose keys are not exactly
   `{source, question, task}` at `cloze_anchor.py:173-175`. Therefore every
   cloze question that passes SELF and SOURCE crashes before classification;
   it cannot produce an E/C/N/U anchor. The new intended end-to-end test
   reproduces this directly:
   `tests/test_cloze_anchor.py::test_source_anchor_uses_role_coordinates_and_never_receives_unmasked_claim`
   fails with `ValueError: unexpected fields in blind source request`.

   Preserve the independent-verifier contract by allowing exactly the
   internal `source_answer=None` sentinel and removing it before composing the
   source-visible payload (or stop adding that sentinel in `_source_anchor`).
   Keep rejecting any non-null answer and any other unexpected key. Add the
   passing source-anchor integration regression to the required test command.

### Required

1. **The persisted framing record is not a record of the generated raw
   output.** `FrozenReader.ask()` calls
   `tokenizer.decode(...).strip()` before `parse_framed_json()` at
   `frozen_reader.py:136-139`. This erases leading and trailing whitespace
   before `raw_sha256`, `raw_prefix`, `raw_suffix`, and `raw_root_span` are
   created. It contradicts the v3 raw-unchanged/lossless-framing contract and
   makes a whitespace-only generation indistinguishable from a strict clean
   one. Decode without stripping and let `parse_framed_json()` determine the
   framing classification.

2. **Sidecar coordinates are accepted as mutable claims, so equal referents
   can be rebound to the wrong role.** `bind_cloze_condition()` only checks
   that the supplied `question_span` contains the sidecar's value
   (`cloze_anchor.py:143-152`); it never proves the coordinate is the one
   generated for that role from the raw role/decontext binding. In the supplied
   reflexive example, replacing the subject's sidecar span with the object's
   span succeeds because both read `"The crane"`. The condition row remains
   syntactically valid but its recorded question/source evidence linkage now
   names the wrong role. Reconstruct and validate the cloze sidecar from the
   compiled immutable role bindings before source validation, or store and
   verify a canonical sidecar digest plus each role's source/response span.
   The repeated-referent regression should include this altered-sidecar
   rejection case.

3. **Framing outcomes are stored per reader-cache entry but never counted in
   a frozen run artifact.** `FrozenReader` writes `json_framing`, but no A
   artifact, merge artifact, or runner summary aggregates strict, recovered,
   and unrecovered outcomes. An audit reader therefore cannot distinguish an
   A-stage with many boundary recoveries from one with strict output without
   independently scanning mutable cache files. Carry deterministic counters
   into the phase artifact (including quota/context failures as failures, not
   recoveries) and expose them in the final coverage/result record.

## Confirmed behavior

- Source payload composition uses the masked cloze plus role-keyed non-target
  conditions and `task`; it does not serialize the unmasked assertion,
  response answer, or target role. The alias guard covers all of those
  source-visible fields. The source text itself is retained as evidence and
  may naturally contain the answer.
- The cloze prompts require one exact row per condition role and preserve the
  distinction between missing premises and target absence. Atomic condition
  validation rejects missing, duplicate, extra, and value-mismatched rows.
- `cloze_candidate()` retains uncovered alphanumeric material as named
  conditions. The atomic compiler trims role quotes only for binding while
  retaining raw frame calls.
- `audit_prepare` uses `build_cloze_anchors`, protocol v3 identifies the
  cloze and framing contracts, and `audit_runner.code_manifest()` includes the
  three new modules. Word-level result coverage remains generated by the
  established anchor path.
- `parse_framed_json()` itself preserves raw prefix/suffix/root coordinates,
  classifies fences and allowed terminal punctuation as recovered, and rejects
  second values or prose tails. The loss occurs only at the FrozenReader call
  site described above.

## VERIFY-boundary re-review — 2026-09-13

The Critical interface failure is closed. `_source_anchor()` now sends both
SOURCE and VERIFY through `source_qa_request()`, and `ClozeReader` retains its
strict `{source, question, task}` allowlist. Thus neither request receives an
answer field, including a null sentinel. The source-anchor integration test now
passes while continuing to assert that `source_answer` is absent from its
source-visible payload.

The remaining status is **Critical 0, Required 3**: the raw-output `.strip()`,
mutable same-value sidecar coordinate binding, and absence of a frozen framing
outcome aggregate are unchanged. They are independent of the repaired VERIFY
boundary.

## Remaining-required re-review — 2026-09-13

**Critical 0, Required 0.** The three Required findings above are closed.

- `FrozenReader` now hands the decoded string to `parse_framed_json()` without
  trimming it and persists that same string as `raw_output`. Its accounting
  records every returned request; `reader_error` takes precedence over a
  framing state, while `cache_hits` is an independent counter. A-stage freezes
  its aggregate, C-stage freezes per-question deltas, and merge combines both
  into `reader_request_accounting`.
- The cloze sidecar now carries a canonical digest and question hash. Before a
  source payload is composed it is checked against the compiled candidate;
  every non-target role's original response span, value, condition set, target,
  masked text, role bindings, aliases, and decontext table must agree. Binding
  rechecks the digest and question hash, so an exchanged same-value referent
  coordinate is rejected.
- The accounting regression exercises raw reconstruction plus cache hits and
  verifies that context-limit, invalid-JSON, and generation-limit outcomes are
  failures rather than framing successes. The merge regression confirms that
  A and C accounting remain visible even with no certificate.
