# 逐 token 无监督检测：本轮实现完成，效果失败

2026-09-29。新主候选 reset_cad_tail 已完成真实8B前向和冻结后评价。它实现了逐词独立因果评分，但没有改善事实错误检测；不替换原默认，不在已见标签上调 K、alpha、方向或融合权重。不存在本轮全2700答成绩。

## 做了什么

来源保留/来源 key 屏蔽两条件，prompt 长度与绝对位置不变；完整历史/干净 prompt KV 加最近16词重算两种历史，共4分支。每个原始token都读完整词表，q=softmax(2 z_source−z_masked)，主分数为原词低概率尾质量的负对数。最近16词是上下文限制，不是风险平均；不广播句子分数、不用未来token、不人工指定竞争词。

分布对比借鉴 [Context-aware Decoding, NAACL 2024](https://aclanthology.org/2024.naacl-short.69/)；原论文讨论生成忠实度，不能据此声称检测有效或CAD首次提出。完整冻结方案见 PLAN_ZH.md；代码镜像见 PLAN_ZH.md。

训练、计算分数和阈值不读取自然真假标签。全部74答分数保存后，以无标签dev混合分布等来源/回答权重95分位定阈值，再读评价标签。设计参考了已知历史失败，不能说全流程无标签发现或独立盲测。

## 主要问题已暴露到哪里

1. **逐token接口不等于逐token有效信号。** 原来源单元均值与路由离线窗口确实损害精细定位，但直接去平均原来源的官方8答AUC仅.5776、新三任务.7765/.6247/.6277。均值去掉后噪声暴露，不能靠接口改造解决真假。
2. **模型惊讶不等于事实矛盾。** 新方法最高误报包含1516/8422/11104的开头“Sure”（28.96/28.02/26.88），都不是标注事实错误。15555错误扩写中的“gear”只有.1476、“aware” .1494，流畅的错误续写可获低风险。这些是冻结后错误诊断，不用于调参。
3. **重置历史会同时破坏正确依赖。** 不重置full_cad_tail在新增Summary/Data2txt为.6251/.6544，重置后.5876/.6122；本轮不能支持“截断历史普遍消除自证”。K=16不是语义状态，也没自动识别何时关系改变。
4. **来源支持仍缺少关系适用性。** q只问“来源使哪个词更可预测”，未问数字/否定/属性绑定到哪个对象。来源同时含多个合法值时，错误配对也可能有高概率。本轮没有证明自动关系读出成立。
5. **无标签混合95分位不能控制正常误报。** dev每RAG任务仅4答，且含未知真假混合；token多次检测会放大any-alarm。不能把阈值叫5%正常FPR，更不能通过查看这批真假重新定阈值。
6. **干预与观察者偏差仍在。** 来源key屏蔽改变模型输入分布，8B与原大模型文风不同；GSM首词query仍保留最后prompt分隔符残差。不能将条件差解释为删除了全部来源文字或得到原生成器内部机制。

## 下一机制门：尚未运行

保留这次逐token原生执行器和完整候选记录，停止把低概率尾质量当主判据。下一问题应是：当前词依赖的来源信息是否随其角色绑定变化而变化，而非泛化的来源有用性。

先在同值异角色、同输出、匹配词项/位置的受控输入上，预先锁定来源块交换、关系词交换、联合交换以及无关块/sham对照；测当前候选margin与KV状态的交互响应。模板构造提供干预对应关系，不用自然真假标签训练或选头；合成机制成功仍不等于自然检测成功。不得人工把自然问题的正确实体/证据角色塞给检测器。

自动来源块/关系对应读出是尚缺的组件，需先用模板隔离检验能否超过词项/位置和随机干预控制。若过关，再在同一8B生成的新来源回答上冻结无监督分数与校准；自然标签最后评价首错定位、正常any-alarm、任务差异和成本。若过不了，不再叠加平滑/有界修正掩盖该缺口。
