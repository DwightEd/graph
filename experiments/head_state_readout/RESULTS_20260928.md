# 逐token误报审计与完整头状态读出：四轮实测

2026-09-28。使用 analyze-results、run-experiment。复用48答6463token的真实8B内部缓存，新增CPU特征与评分，没有新GPU前向，没有重跑2700答。每轮计划先于该轮评分，原始结果分目录保留。

## 结论

雅可比和JS已经进入本轮实际检测，不再仅作为解释图。完整逐头模式＋条件参考＋来源融合提供局部改进，但尚不能统一检出所有错误，也没有解决所有正常误报。v3预先列出的融合候选检95/134错、误报147/1353，平均答内AUROC .7507；同尺度旧固定融合20/71、.7377，旧范数路由56/311、.6369。比路由好，比固定融合多报76个正常词，不能只拿95对20宣称无代价提升。

无标签dev CDF统一任务尺度后的事后ROC预算分析：最多71个正常误报时，v3融合排序可检49错，旧固定融合20错；最多61误报时37对16。这个阈值由评价标签描述ROC包络，**没有部署**，不冒称现成检测点。没有新全量QA AUROC，也不能将本地.7507与旧全QA .8907横比。

自然洋葱局部AUC从旧路由0提升到.9048，检3/7错、0/3正常误报；头饰主关联分数AUC .4273，11错仍全漏。尚未达成全部漏检修复，不替换默认、不启动全测试。

## 真正使用了哪些量化工具

消息 m[l,h,t,j]=A[l,h,t,j] W_O[l,h] V[l,j]。三类完整视图：

- 读取/整合：1024物理头的norm/net路由、source/history抵消，以及全部source/history跨头Gram余弦（上三角是对称矩阵等价表示）。
- JS：source attention→payload、payload→|门导数|，以及原逐头direct/relay attention、direct/relay influence、read/use JS。缺失relay保留NaN，拟合参考中位填补并附缺失mask，不补成“完全一致”。
- 雅可比作用：每头prompt/history正、负原生门导数比例，residual/FFN抵消；三指定方向的完整4096维hidden JVP、完整词表Fisher Gram与候选margin响应。三方向JVP不是完整模型Jacobian，当前query响应也不是完整历史因果重算。

每token保存59401坐标，含1024头与完整关系；没有PCA/低秩/自动标签选头，没有重建误差训练。原始A、V、逐key门导数和4096维向量继续保留，派生视图不替代原缓存。

第一轮每来源最多64个等间隔参考token（4fit来源/task），按参考中位/IQR度量完整坐标距离，各视图等权。每个来源先按熵、surprisal、位置、prompt长度、原路由、自动词面类别、是否在prompt出现选择16个条件邻居，再按完整状态选8个。计算当前距离除以邻居在排除自身来源后的参考距离。这是局部距离比，不是幻觉概率，也不是标准LOF的逐字复现；[异常检测文档](https://scikit-learn.org/stable/modules/outlier_detection.html)支持密度比较思想，但也明确异常与新颖分布的假设边界。

第二/三轮把条件改为“生成条件＋读取模式”，比较采纳侧距离，反向再比较读取侧，取两者几何均值。第三轮读取保留所有头的4维观测，采纳保留所有头的JS和Jacobian作用；整体hidden方向/整体Fisher/Gram作为前轮对照保留。此处保留头信息，不等于给每头无限权重；最终标量仍需独立检验可分性。

评分和参考拟合均不读真假标签，阈值来自4dev/task来源等权无标签混合95分位。它不保证正常FPR=5%。整体算法设计已经参考本地标签与错误分析，因此准确表述是“标签辅助机制开发，无标签拟合和推理”。另有一个明确隔离的监督诊断，不能冒称无监督成绩。

## 为什么表征有差异，最终分数仍分不开

1. **保留差异不等于知道差异对应的真假方向。** 原全头平均会抵消相反头模式；本轮完整坐标避免该问题，但“少见”与“错误”仍不同。头饰错误关联分数约.999–1.775，正确约1.033–1.477，阈值1.906。要让这11错全部超过单一阈值，10个正确词也全部误报。这是当前标量排序的实测下界，不是调低阈值能解决的问题，也不证明原表征不可分。
2. **错误确实读了并利用了prompt内容。** 头饰正确局部source attention均值.1640，错误.1913；自动最高读取/原生作用地址分别是cloth/folded/cap和fringe/gold/feathers。原文“Only the Inca…”的内容被错误泛化。洋葱正确/错误source attention .1734/.1702近似，但作用地址从low heat转向另一阶段的10/12 minutes。缺的是适用范围/阶段绑定，不能由来源强度独自判定。所有地址自动由原张量排序，未把实体/约束标注送入检测。
3. **输出作用大小不是事实支持。** Jacobian可清楚显示gold或12确实在推动当前生成；这种高作用也能稳定推动错绑。整体hidden方向反映正常语义差异，未必适合当全局异常分数。
4. **不同错误的“好模块”会互相压制。** v3补出大量烹饪/时间词，却压掉WiFi；说明统一等权融合不是完整解决方案。未检39词中31词的token ID出现在prompt，而95个检出错词中48词出现；这只是词项匹配诊断，不能证明复制导致错误，但与错绑型困难一致。

额外监督诊断仅用于发现先验：用一题正负局部均值确定方向，在另一题评价。JS跨题AUC .857/.664，逐头Jacobian .857/.600；完整hidden tangent .429/.464，整体Fisher .381/.427。联合全部块反而.714/.555。标签确实能发现部分可迁移方向，但只有两题，既不是可泛化结论，也不能把该方向写入无监督检测器后隐瞒监督。

## 当前统一方法与下一步的明确边界

已实现的逻辑是：旧来源/路由保留粗风险 → 完整头读取/整合状态 → JS与Jacobian测量采纳 → 相似生成及读取条件下的联合比较 → 独立混合校准 → token评价。它避免按单个符号判错，在洋葱和若干回归span上产生实际改善，但条件异常仍不足以识别稳定错绑。

下一步应针对头饰、养老金、四天三个仍漏类型，把当前及历史选择的**具体来源地址关联**接到逐头作用上，比较内容与限定/阶段信息是否共同影响选择；原始全key矩阵已保留，不需要预标实体。不能仅再调全局JS权重、再加一个谱熵或传播现有风险：这些都可能将正常复述扩成错误。这个地址关系检测器尚未实现，没有成绩，不作为本轮交付冒充成功。
