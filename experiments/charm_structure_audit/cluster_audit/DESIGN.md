# 研究问题 → 配对 → 测量 → 模型依赖

## 1. 关键反例

假设模型对所有紧密聚集的区域都打高分，而数据里普通正常词远多于正常聚集段。
它仍可能获得很高的整体token AUROC，却无法区分“聚集的错误续写”和“聚集的正确续写”。
因此，聚集本身的标签相关性、同错误span相似性和去边后全体分数下降，都不能独立回答本问题。

本次主要问题：在同回答、同长度、相似聚集结构条件下，错误token是否仍能排在正常token前面？
次要问题：使这种区分成立的信息已经存在于简单逐头统计中，还是需要邻居配对、共同读取与中继？
这审计的是已训练检测器的统计依赖，不直接证明生成LLM的幻觉因果机制。

## 2. 匹配的定义

原标注映射成半开token区间；仅合并重叠，不合并相邻片段。正常候选枚举同答等长连续区间，
区间内全部无标注错误且offset有实际文本。匹配不读取score或任何学习表征。
主分析没有跨回答补匹配，因此全错回答、正常余量不足、首错太靠前等情形可能无法配对。
需报告遗漏范围，不能把配对结果当作全部错误的结论。

基础条件：相对起点位置差≤0.25；token-ID重复比例差≤0.15；首token表面类别相同；
是否已有先前错误相同。表面类别仅number/word/punctuation/empty，不是词性/语义角色。

对长度m的区间S，令 E_SS 为原union图两端均在S内的历史边，E_RS 为指向S的全部历史边，
M_SS为段内边的保留多头权重总量，M_all为进入S的全部保留权重总量：

| 描述符 | 定义 | 最大绝对差 |
|---|---|---:|
| internal_density | |E_SS| / (m(m-1)/2) | 0.10 |
| internal_edge_share | |E_SS| / |E_RS| | 0.10 |
| internal_mass_share | M_SS / M_all | 0.10 |
| lag1_share | E_SS中距离为1的比例 | 0.10 |
| hub_concentration | Σ_source (该源的段内边数 / |E_SS|)^2 | 0.10 |
| log_mean_edge_mass | log(M_SS / |E_SS|) | 0.50 |
| log_in_degree | log(1 + 区间平均入度) | 0.50 |

这里汇总头权重只用于控制“整体聚集程度”；没有把这种汇总送回检测器。
匹配要求所有caliper通过，不以平均距离掩盖某一项严重不匹配；距离仅用于选最近合格候选。
两个区间都必须有实际内部边。阈值固定是可执行的初始研究协议，不是已验证最佳标准。
必须检查balance表；统计描述符相近不能被写成精确相同的拓扑。

第三层在结构匹配之外控制每个head的段均值向量：自关注、入边总质量、入边条件熵。
熵仅对正的保留权重重新归一化，以log(非零入边数)归一到0～1；空入边记0并同时保留总质量。
这不是完整attention熵，不是logits熵，阈值以下丢弃的质量没有恢复。
每类统计的逐头RMS差≤0.05，最大逐头差≤0.25。保存两种差，不声称每个头完全相等。

实现：`features.prepare_features/structure_at/marginal_windows` →
`matching.candidates/pair_options/choose_disjoint`。
预处理按边分块，逐头累计；不重建完整N×N×layer×head张量。
读取一份图后完成匹配、逐头差异与表征诊断再释放，不集合所有图常驻内存。

## 3. 指标的统计单位

第k对错误区间H_k与正常区间N_k等长m_k，使用冻结score：

    A_k = (1/m_k²) Σ_{i∈H_k,j∈N_k} [1(s_i>s_j) + 0.5×1(s_i=s_j)]

主指标是A_k的配对宏平均和source均值，置信区间按source重采样。
另报按相同相对token位置比较的胜率、区间均值胜率、原阈值下错误recall和正常cluster FPR，
以及错误起点命中、正常区间起点误报。正常区间起点不是标注正确命题的语义起点。

片段均值只是辅助，不做“命中一点就给整段判对”。普通总体AUC及其错误/首错分母仍另存。
配对后的正负token比例为1:1；AP只作为该配对任务的指标，不与原不平衡全数据AP直接类比。
context/cluster/cluster_heads之间有不同覆盖，另保存共同错误span子集；此时正常控制仍会改变。

实现：`reporting.evaluate_pair/summarize_pairs/source_mean`。

## 4. 从“有差异”走向“模型真的用了差异”

在**固定配对清单**上比较原模型与已有控制。对于每一控制，既看错误侧变化，也看正常侧变化，
尤其看配对AUC和错误减正常的分数间隔。两类一起降分不是区分能力的证明。
每个对照的缺测必须在原模型一侧同样排除；prefix只可测起点时单独记录起点覆盖。

逐头profile保留L/H并计算错误减正常的source均值：自关注、入边总质量、保留熵、prompt份额、
段内份额。前几项即使匹配过仍列出来以检查平衡，后两项是未被完全控制的候选路由区别。
它们的统计差异不能冒充模型重要性。所有头全部导出，探索性区间不作多重校正结论。

从已存embedding和deep_audit的projected/layer_*表征，比较：错误段内部cosine、正常段内部
cosine、两段间cosine。两类都紧密但彼此可分才值得继续；余弦变化不是读出准确率提升。
真正的编码增益要在同一配对上对比原属性读出、GNN读出及独立node_only等模型结果。
本增量只接入已有逐token结果，不偷偷再训练读出或检测器。

实现：`io.load_capture/read_comparisons`；`features.head_profile/representation_geometry`；
`reporting.summarize_pairs`的共同配对控制比较。

## 5. 验证与未完成的科学证据

软件测试构造普通正常词很多、错误span和正常聚集span同样高分的例子：总体AUROC>0.9，
配对AUROC=0.5，正常聚集token FPR=1。它证明新统计能揭示该评价反例，**不是自然数据结果**。
测试还验证score盲匹配、重复/相邻span规则、不重用正常token、无合格控制不补数、逐头保留、
共同控制覆盖、原阈值严格大于、source重采样、跨模型各自阈值、原数据不修改和实际CLI。
没有收到真实数据的新报告前，不得写“CHARM就是认聚集”或“CHARM已学到事实关系”。
